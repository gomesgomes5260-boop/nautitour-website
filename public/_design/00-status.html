3Plano de início — UI/UX

Roadmap de 6-8 semanas para elevar o visual de MVP para produto sério

Filosofia

Não jogue fora o que funciona. O site converte hoje. O redesign deve amplificar a conversão, não trocar componentes que já vendem. Trabalhe seção por seção, com release incremental, mantendo a operação rodando.

Fases

Semana 1 · Discovery

Fase 0 — Audit do site atual

  • Screenshots de todas as páginas (home, escuna, lancha, locacao-escuna, checkout, reserva, pagamento, login, signup, admin) em desktop + mobile
  • Inventário de componentes existentes — listar tudo que aparece (cards, botões, inputs, modais) pra montar base do design system
  • Análise de concorrentes: Buscaape Maragogi, Get Your Guide (Brasil), Airbnb Experiences, Civitatis — capturar padrões de "venda de passeio náutico"
  • Métricas atuais (se houver) — taxa de conversão, abandono no checkout, dispositivos. Se não houver, instalar Vercel Analytics ou Plausible agora
Semana 1-2 · Estratégia

Fase 1 — Personas + Brand voice

  • 3 personas principais: família em férias com crianças, casal em aniversário/lua-de-mel, grupo de amigos (lancha privativa)
  • Customer journey por persona — onde descobre, o que pesquisa, o que decide a compra, dúvidas comuns
  • Brand voice: tom caloroso, confiável, focado na emoção do passeio (não em logística). PT-BR informal mas profissional
  • Princípios de design (3-5): ex. "fotos vendem mais que texto", "preço sempre claro", "checkout em 1 tela", "mobile-first absoluto"
Semana 2-3 · Identidade

Fase 2 — Sistema visual

  • Paleta refinada: manter #096EAB + #D90006 como anchor, adicionar tons neutros (warm grays), areia, sunset. Define escala (50-900 por cor)
  • Tipografia: escolher webfont (sugestões: Inter pra UI, ou par display+text como "Fraunces + Inter"). Mobile sizes mínimos 16px body
  • Espaçamento e radius: escala 4px base, radius padrão 8px ou 12px
  • Iconografia: continuar com lucide-react (boa biblioteca, já no projeto)
  • Tokens em Tailwind v4 config — CSS vars (Tailwind 4 já é CSS-first) pra cores, espaçamento, radii. Permite dark mode no futuro
Semana 3-4 · Design System

Fase 3 — Componentes

  • Componentes base (Figma + código): Button (5 variants), Input, Select, Card, Modal, Toast, Pill/Badge, Skeleton, Loading
  • Componentes de negócio: TourCard, PriceTag, DateTimePicker, PassengerCounter, BookingSummary, PaymentMethodSelector, CountdownTimer (já existe!)
  • A11y: usar Radix UI Primitives como base (focus management, keyboard nav, ARIA) — não estiliza, só dá acessibilidade. Combinar com Tailwind
  • Animações: Framer Motion para micro-interações sutis (hover de card, transição de modal). Não exagerar — Maragogi vende viagem, não app de fintech
  • Documentar componentes em Storybook (opcional) ou em código com comentários
Semana 4-7 · Redesign

Fase 4 — Páginas (priorizado por conversão)

  • P0 (Semana 4-5): / (home), /passeio-escuna, /passeio-lancha — páginas de descoberta. Foco em fotos grandes, prova social, urgência sutil
  • P1 (Semana 5-6): /checkout/[scheduleId], /reserva/[code], /reserva/[code]/pagamento — flow de conclusão. Reduzir fricção, sumarizar valor, countdown claro
  • P2 (Semana 6-7): /locacao-escuna (lead capture lancha privativa), /sobre-nos, /politica-de-cancelamento
  • P3 (depois): /admin/* — operacional, menor prioridade visual mas merece atenção a usabilidade
  • 1 PR por seção redesenhada — mantém site em produção rodando enquanto novas seções entram
Paralelo a 4 · Conteúdo

Fase 5 — Foto + copy

  • Sessão de fotos profissionais da escuna em Maragogi (hero shots, passageiros felizes, drone, sunset). Sem isso, redesign fica genérico
  • Backup: Unsplash + AI generation para preencher gaps temporários
  • Copy persuasivo: revisar todos os títulos de página, CTAs, descrições. Linguagem orientada ao benefício ("uma manhã com as crianças no mar"), não à feature ("3h de duração")
  • Testimonials reais — coletar de clientes pós-passeio (via Resend pode ser automatizado)
Final · Validação

Fase 6 — Teste + iteração

  • User test com 3-5 pessoas da persona-alvo (família/casal). Tarefa: "reserve uma escuna pra domingo". Gravar tela + comentários
  • Métricas comparadas: taxa de conclusão de checkout antes vs depois
  • Heatmaps opcionais (Hotjar/PostHog) na home e checkout pra ver onde olho cai
  • Iterar 2 semanas após launch
